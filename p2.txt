REQUIREMENTS:

A. Signup
Implement:
POST /api/auth/signup

Accept:
{
  "name": "User Name",
  "email": "user@example.com",
  "password": "StrongPassword123"
}

Requirements:
- Validate request body using Zod.
- Trim name and email where appropriate.
- Validate email format.
- Apply a reasonable password length requirement.
- Check whether the email already exists.
- Hash the password using bcryptjs before storing it.
- Never store or return a plaintext password.
- Return an appropriate success status and safe user data.
- Handle duplicate email without exposing database internals.

B. Login
Implement:
POST /api/auth/login

Accept:
{
  "email": "user@example.com",
  "password": "StrongPassword123"
}

Requirements:
- Validate request body.
- Find the user by email.
- Compare password using bcryptjs.
- Return a generic invalid-credentials error for an incorrect email or password.
- Generate a JWT using jsonwebtoken.
- Use JWT_SECRET and JWT_EXPIRES_IN from the existing environment configuration if available.
- Do not hardcode secrets.
- Return the token and safe user details.
- Never return password_hash.

C. JWT Authentication Middleware
Create or update the authentication middleware.

Requirements:
- Read the token from the Authorization header in the format:
  Bearer <token>
- Verify the token using the configured JWT secret.
- Reject missing, malformed, expired, or invalid tokens with suitable 401 responses.
- Attach the authenticated user's safe identity to req.user.
- Do not trust user IDs sent in request bodies for authentication.
- Keep the middleware reusable for future protected routes.

D. Current User Endpoint
Implement:
GET /api/auth/me

Requirements:
- Require a valid JWT.
- Return the authenticated user's safe profile.
- Do not return password_hash or other sensitive fields.
